  • Bard song damge modifier (not working again)
    DefectShipped · Merit awardedJune 24th, 2026Credit: Y a z k i r
    The damage on bard song isn't correct: 38 bard, 121 perform, giving +D4 damage? (expecting +6 instead at this skill and bard level, per Bard Song customized to mirror the customized Curse Song) -- Bruno Mars is the character

    Root cause was that EffectDamageIncrease takes a DAMAGE_BONUS_* constant, not a flat integer — the raw value 6 was being read as DAMAGE_BONUS_1d4, so the top tier rolled 1d4 instead of applying a flat +6. The identical bug was fixed in the matching Curse Song (x2_s2_cursesong) damage tiers (raw 6/8/10 were rolling 1d4/1d8/2d6, now flat −6/−8/−10). Tiers 1–5 were always correct and are unchanged; only the damage column was affected.

  • Weapons with both Attack Bonus (AB) and Enhancement Bonus (EB) appear to mis-calculate stats
    DefectShipped · Merit awardedJune 23rd, 2026Credit: Piskan (Alec Cain)

    Root cause is hardcoded NWN engine behavior, not a module bug: the Attack Bonus property and the attack component of the Enhancement Bonus property do not stack — the engine applies only the higher of the two to the attack roll — while the enhancement's damage and damage-reduction bypass always apply. A weapon carrying both therefore shows a confusing character sheet, and any Attack Bonus ≤ the Enhancement Bonus is dead weight.

    There is no global toggle for this, so we audited every weapon. 199 weapons (blueprints plus all placed/inventory instances) carried both a generic Attack Bonus and Enhancement Bonus; each was collapsed to a single Enhancement Bonus. Where Attack Bonus exceeded Enhancement, the kept value was set per-item to a balanced figure between the two. Driven by bin/ab-enhance-audit.py → ab-enhance-audit.csv → bin/ab-enhance-apply.py.

    Follow-up (player report: Chosen Kama still +13/+13): the first pass matched the Attack/Enhancement properties only when their unused subtype was encoded as 0, but NWN also encodes it as 65535 (0xFFFF).
